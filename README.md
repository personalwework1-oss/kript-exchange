# kript-exchange

Некастодиальная биржа: интерфейс как у биржи, деньги и ключи — только у пользователя.

## Структура

```
apps/
  mobile/             мобильное приложение (Expo / React Native), этап 2
    src/app/          экраны (expo-router): онбординг, вход, рынки, торговля, активы, получить, отправить, настройки
    src/wallet/       состояние кошелька, хранилище в Keychain/Keystore, балансы
    src/market/       цены и свечи (пока CoinGecko, позже — наш сервер)
packages/
  wallet-core/        ядро кошелька (этап 1)
    src/
      chains.ts       сети и адреса контрактов USDT
      mnemonic.ts     сид-фраза BIP39
      derive.ts       адреса для всех сетей из одной сид-фразы
      slip10.ts       деривация ключей Solana (ed25519)
      vault.ts        шифрованное хранилище (пароль и/или passkey)
      networks/       балансы и переводы: bitcoin, evm (ETH/BSC/Polygon), tron, solana
    test/             тесты
    scripts/          утилиты для разработки
```

## Что умеет этап 1

| Сеть | Адрес | Монеты | Путь деривации |
| --- | --- | --- | --- |
| Bitcoin | bc1q… (native SegWit) | BTC | m/84'/0'/0'/0/i |
| Ethereum | 0x… | ETH, USDT (ERC20) | m/44'/60'/0'/0/i |
| BNB Smart Chain | тот же 0x… | BNB, USDT (BEP20) | m/44'/60'/0'/0/i |
| Polygon | тот же 0x… | POL, USDT | m/44'/60'/0'/0/i |
| Tron | T… | TRX, USDT (TRC20) | m/44'/195'/0'/0/i |
| Solana | base58 | SOL, USDT (SPL) | m/44'/501'/i'/0' |

Пути совпадают с MetaMask, Trust Wallet, TronLink и Phantom: сид-фразу можно импортировать туда и увидеть те же средства.

**Хранилище (vault):** сид-фраза шифруется случайным ключом (AES-256-GCM), а этот ключ — отдельно для каждого способа входа: пароль (scrypt) и/или passkey (WebAuthn PRF → HKDF). Один и тот же зашифрованный файл можно хранить на телефоне и в облаке пользователя.

**Защита при переводах:**
- проверка адресов (контрольная сумма EIP-55, сеть Bitcoin, Solana — только адреса кошельков);
- запрет перевода на сам контракт USDT и самому себе;
- проверка, хватает ли денег на сумму и комиссию;
- перед подписью ключ сверяется с адресом отправителя;
- Bitcoin: перед подписью проверяется, что получатель получает ровно нужную сумму, а сдача уходит только нам; отсечка безумных комиссий;
- Tron: транзакцию собирает нода, поэтому перед подписью она полностью перепроверяется (получатель, сумма, контракт, хэш);
- приватные ключи затираются в памяти сразу после подписи.

## Этап 2: мобильное приложение

- Создание кошелька: 12 слов → проверка 3 случайных слов → пароль → (по желанию) Face ID / отпечаток.
- Импорт по сид-фразе из MetaMask, Trust Wallet, Phantom и др.
- Хранение: зашифрованная сид-фраза в Keychain (iOS) / Keystore (Android), только на этом устройстве.
  Face ID открывает случайный 32-байтный ключ, который расшифровывает хранилище — биометрия никогда не видит сид-фразу.
- Автоблокировка через 2 минуты в фоне, повторная биометрия на каждый перевод.
- Рынки (цены, изменения, мини-графики), торговый экран со свечным графиком (обмен — этап 3),
  портфель с балансами по всем сетям, получение (адрес + QR), отправка с проверкой и экраном подтверждения.
- По умолчанию **тестовые сети**. Основные включаются переменной `EXPO_PUBLIC_NETWORK=mainnet`.

### Запуск на телефоне (Android, самый простой путь)

1. `npm install` в корне проекта.
2. Создайте `apps/mobile/.env` по образцу `.env.example` (ключи можно оставить пустыми — будут публичные узлы).
3. Зарегистрируйтесь на expo.dev, затем:
   ```bash
   cd apps/mobile
   npx eas-cli@latest login
   npx eas-cli@latest build --profile preview --platform android
   ```
4. EAS пришлёт ссылку на APK — откройте её на телефоне и установите.

Для iPhone нужен Apple Developer ($99/год): `npx eas-cli@latest build --profile preview --platform ios`.

> Expo Go для SDK 58 пока не во всех магазинах, поэтому используем свою сборку (development/preview).

### Разработка с горячей перезагрузкой

```bash
npx eas-cli@latest build --profile development --platform android   # один раз, ставим на телефон
cd apps/mobile && npx expo start                                     # дальше — код обновляется на лету
```

## Этап 3: обмены

Покупка и продажа за USDT прямо из кошелька пользователя, рыночные ордера.

| Монета | Сеть | Агрегатор |
| --- | --- | --- |
| ETH, LINK | Ethereum | 0x Swap API v2 (AllowanceHolder) |
| BNB | BSC | 0x |
| POL | Polygon | 0x |
| SOL | Solana | Jupiter Swap API V2 (/order + /execute) |
| TRX | Tron | SunSwap V2 (этап 5) |

BTC и остальные монеты пока только отслеживаются (обмен BTC — через кросс-чейн, в следующих этапах).

**Проверки перед подписью (packages/wallet-core/src/swap):**
- 0x: токены, сеть и сумма совпадают с запросом; транзакция — это именно `AllowanceHolder.exec` с нашим токеном и суммой;
  approve только на этот контракт и **ровно на сумму сделки** (никогда «безлимитно»); ETH отправляется только при продаже ETH и ровно на сумму;
  минимум к получению не ниже допустимого проскальзывания (максимум 3%).
- Jupiter: транзакция **симулируется на нашем RPC** до подписи — пользователь тратит не больше суммы (+0,01 SOL на комиссии/аренду)
  и получает не меньше гарантированного минимума; кошелёк должен быть подписантом, плательщик комиссии — сам пользователь или объявленный кошелёк Jupiter.
- Котировка живёт 30 секунд, после — только обновление.

**Комиссия сервиса** (`apps/mobile/.env`):
- EVM: `EXPO_PUBLIC_FEE_BPS` (30 = 0,3%) и `EXPO_PUBLIC_FEE_RECIPIENT_EVM` — ваш адрес.
- Solana: реферальный аккаунт Jupiter `EXPO_PUBLIC_JUP_REFERRAL_ACCOUNT`, 50–255 bps (Jupiter оставляет себе 20% от вашей комиссии).

**Ключи:** `EXPO_PUBLIC_0X_API_KEY` (dashboard.0x.org, бесплатно), `EXPO_PUBLIC_JUP_API_KEY` (developers.jup.ag/portal; без ключа — 0,5 запроса в секунду).

> Обмены работают только в основных сетях (`EXPO_PUBLIC_NETWORK=mainnet`): агрегаторы не поддерживают тестовые сети. Проверяйте на маленьких суммах.
> В продакшене ключи агрегаторов нужно спрятать за наш сервер — сейчас они попадают в сборку приложения.

## Этап 6: токены

**Проверенные токены** (`packages/wallet-core/src/tokens.ts`), 36 штук в 5 сетях:

| Сеть | Токены |
| --- | --- |
| Ethereum | USDT, USDC, DAI, WBTC, LINK, UNI, AAVE, PEPE, SHIB, LDO, ONDO, ENA |
| BNB Chain | USDT, USDC, DAI, LINK, UNI, AAVE, FLOKI |
| Polygon | USDT, USDC, DAI, WETH, WBTC, LINK, AAVE |
| Solana | USDT, USDC, JUP, BONK, WIF, RAY, PYTH, JTO, TRUMP, POPCAT, ORCA |
| Tron | USDT, USDD (2.0), BTT, JST, SUN |

- Адреса EVM и Solana **сверяются в тестах** с официальным списком Uniswap (`@uniswap/default-token-list`): адрес, знаки, символ.
- Адреса Tron — из источников проектов (объявление SUN.io про USDD 2.0, TRONSCAN для JST и др.).
- В приложении каждый проверенный токен **ещё раз сверяется в блокчейне** (знаки после запятой и символ). Расхождение — токен помечается «Возможная подделка».

**Всё остальное:**
- **Автопоиск** токенов на адресе: Solana (RPC, включая Token-2022), Tron (TronGrid), Ethereum/Polygon (если RPC — Alchemy).
- **Неподтверждённые токены скрыты** в отдельный раздел с предупреждением. Токен с символом проверенного (например, «USDT») но другим адресом — «Возможная подделка».
- **Добавить свой токен** по адресу контракта — данные читаются из блокчейна, проверка на подделку символа.
- **Переводы любых токенов**: ERC20/BEP20, TRC20, SPL и Token-2022.
- **Обмены**: все проверенные токены против USDT — через 0x (EVM), Jupiter (Solana), SunSwap (Tron: любые пары, лучший из маршрутов «напрямую» и «через TRX»).
  Если токен есть в нескольких сетях (например, LINK), на экране торговли можно выбрать сеть.
- Цены и графики токенов — CoinGecko.

## Этап 5: обмен в Tron (USDT TRC20 ↔ TRX)

SunSwap V2 — крупнейшая DEX в Tron (пул WTRX/USDT — десятки миллионов долларов).

- **Роутер проверяется в блокчейне** перед первым использованием: `factory()` должен быть официальной фабрикой SunSwap V2
  (`TKWJdrQkqHisa1X8HUdHEfREvTzw4pMAaY`), а обёрнутый TRX — WTRX (`TNUC9Qb1rRpS5CbWLmNMxXBjyFoydXjWFR`).
  Названия функций (ETH/TRX) читаются из ABI контракта в сети.
- Адрес роутера по умолчанию — `TNJVzGqKBWkJxJB5XYSqGAwUTV15U24pPq`. **Перед запуском сверьте его на tronscan.org** (метка «SunSwap V2 Router»);
  если SUN.io выпустит новый — поменяйте в `SunSwapProvider({ router })`, проверка фабрики защитит от ошибки.
- Все вызовы кодируем сами и передаём ноде как `rawParameter`; транзакцию ноды перед подписью сверяем побайтно
  (контракт, данные вызова, сумма TRX, отправитель, хэш).
- approve — только роутеру и только на сумму сделки, с обнулением ненулевого разрешения (правило USDT).
- Комиссия сети в Tron — энергия: без застейканного TRX обмен сжигает примерно 15–40 TRX. Лимит — 200 TRX.
- Комиссия сервиса в Tron пока не берётся (отдельный перевод USDT стоил бы пользователю ещё ~15–30 TRX).

**Исправлено попутно:** USDT в Ethereum и Tron запрещает менять ненулевое разрешение на другое ненулевое —
теперь в 0x, CoW и SunSwap ненулевое разрешение сначала обнуляется.

**Защита от плохой цены:** если цена сделки хуже рыночной больше чем на 3%, экран подтверждения показывает предупреждение.

## Этап 4: лимитные ордера

CoW Protocol — Ethereum, BNB Chain, Polygon (и Sepolia в тестовом режиме). Пары: ETH, LINK, BNB, POL против USDT.

- Ордер — это **подпись EIP-712**, а не транзакция: размещение бесплатное, деньги остаются в кошельке до исполнения.
- Ордер собирается в приложении, а не на сервере: пользователь подписывает ровно «продать X токена A минимум за Y токена B до даты, получатель — я».
  Хэш типа ордера и домен контракта сверены в тестах с опубликованными константами CoW.
- Разрешение на списание (approve) — на контракт CoW VaultRelayer, на сумму «уже разрешено + сумма ордера», чтобы не ломать другие открытые ордера.
- Продажа ETH/BNB/POL: сначала оборачивается только недостающая часть в WETH/WBNB/WPOL (так требует протокол).
- Идентификатор ордера, который вернул сервер, сверяется с вычисленным локально — иначе ошибка.
- Отмена — бесплатная подпись (OrderCancellations), только своих ордеров.
- Вкладка «Ордера»: открытые и история (исполнен / отменён / истёк), отмена в один тап.
- Комиссия партнёра: `EXPO_PUBLIC_COW_FEE_BPS` (по умолчанию 20 = 0,2%) на адрес `EXPO_PUBLIC_FEE_RECIPIENT_EVM`, берётся только при исполнении.

Для Solana лимитные ордера (Jupiter Trigger) будут позже: у Jupiter сейчас идёт переход на новую версию API, а средства там переводятся в хранилище программы, а не остаются в кошельке.

## Этап 7 — PIN и ложный PIN

- **PIN (6 цифр)** — отдельный слот хранилища: ключ = scrypt(PIN) + HKDF с 32-байтным секретом устройства
  (`kript.dev`, только этот телефон, без бэкапа). Копию хранилища вне телефона перебрать нельзя.
- Попытки: 1–4 без паузы, дальше 30 с → 1 мин → 5 мин → 15 мин → 1 ч; после 10 — PIN отключается до входа по паролю/биометрии.
- Простые PIN (000000, 123456, 121212, 112233…) не принимаются.
- **Ложный PIN** открывает отдельный кошелёк со своей сид-фразой. В хранилище всегда лежит «второе» хранилище
  (`kript.cache.a`): либо ложный кошелёк, либо заполнитель, который никто не откроет; каждый ввод PIN проверяется
  против обоих — по времени и по файлам не видно, настроен ли ложный PIN. Признак включения (`kript.cache.b`) —
  HMAC от настоящей сид-фразы или случайные байты.
- В режиме ложного кошелька: свои добавленные токены, пароль «неверный», настройки показывают «Не настроен».
- Ограничения: Face ID и пароль всегда открывают настоящий кошелёк; часы телефона можно перевести, чтобы
  сократить паузу (лимит в 10 попыток при этом действует).
